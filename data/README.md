# Data dictionary and processing

## Reviewed v2 training versus historical replay

New training reads the raw folders with `reviewed_protocol.py`, not the archived feature tables. It includes all raw sources by default, retains full regular time grids, uses causal PV weather bins, and builds windows within separate chronological train/validation/test intervals. Missing-value estimates, scaling, an empirical power bound, and extreme thresholds use training rows only. Every exclusion and missing-target count is exported. Raw files are not changed. See `../provenance/REVIEW_V2.md` for exact rules and unresolved source definitions.

The table below describes file meaning and, where it names `main.py`, the **historical loader** used for archived compatibility. The later sections explicitly distinguish old and new behavior. Processed folders are archived snapshots, not the output of the reviewed preprocessing protocol.

The code and data are separate. Do not move individual input folders without adjusting the path modules in `code/forecasting/forecast_paths.py` and `code/scheduling/scheduling_paths.py`.

## Vehicle-power columns

`mor`, `noon`, and `eve` select the morning, noon, and afternoon cases. Within each period, columns 1–3, 4–6, 7–9, and 10–12 supply the three devices for initial-charge settings H, M, L, and X respectively. `normal` is the proxy load used by the historical forecast-driven branch. The v2 `fixed_load` default uses the same period/initial-charge columns in both renewable cases. The two CSV files have the same column convention. The preprocessing that originally produced these power CSVs was not found; they are supplied as input records, not claimed to be regenerated by the flight scripts.

## Time, scaling, and model inputs

PV and wind records come from different years. Scheduling selects separate calendar slices and scales each source to a configured station peak. These are not weather measurements collected together at the physical trial site. Historical scaling uses the maximum of the full processed record. The v2 `fixed_load` default uses only observations before the first replay day, applies the same scale in both branches, and clips scaled renewable inputs to the configured station peak. Station power is kW and battery energy is kWh. Archived model fitting is still not independent of replay time, regardless of this scaling correction.

In historical inference, neural inputs are prior feature windows but the physics branch additionally receives target-row weather. Historical training splits each month after forming windows, and the old PV loader compresses daytime records across nights. These limitations remain relevant to archived results. The reviewed training entry instead uses interval-local windows on a full time grid and supplies physics weather from the last past input row after the same missing-sensor mask and imputation as the temporal branch. No target-time weather is supplied to the reviewed predictor.

## Saved results and weights

The distributed processed feature tables and `models/` are matched snapshots. A checkpoint contains `model_state_dict`, `x_mean`, `x_std`, `y_mean`, and `y_std`; the naming `y_mean/y_std` also covers the original min/range target scaling. Preserve them together. `scalers.npz` is retained as an additional source artifact.

`results_reference/forecasting/` holds training histories, test predictions, extreme/missing-input predictions and JSON metrics. `results_reference/scheduling/` holds simulator/replay outputs, not raw live telemetry. References to old absolute paths inside archived JSON are metadata; active code does not use them as input paths. These files are preserved unchanged for traceability.

The available input files did not include dataset licenses or authoritative download records. No data ownership or redistribution rights are inferred from their presence here.
