# Verification performed during packaging

This is the historical v1 verification record. For the v2 protocol, see [REVIEW_V2.md](REVIEW_V2.md) and `reviewed_verification.json`. These software checks do not establish independent forecast accuracy.

Checks were run on Windows with Python 3.12 and CPU PyTorch. Exact installed versions are in `verification_report.json`. The checks used the separated package paths, not the original `local` tree.

| Check | Observed result |
|---|---|
| Source and release integrity | Every selected source is recorded with SHA-256; final release files are listed in `SHA256SUMS.csv`. Original sources are checked again before delivery. |
| Python syntax | All delivered Python files parse, including the separately marked legacy snapshots. |
| Experimental power inputs | Both CSV schemas, all required period/charge columns, finite entries and five-second sample spacing checked. |
| Saved forecasting models | All 36 checkpoints loaded strictly into their reconstructed architectures. Forward prediction and backward calculation passed for each. |
| Saved prediction comparison | First 32 saved normal-test timestamps per model were re-evaluated. Per-model maximum absolute differences are recorded, not assumed to be zero. PV differences were at most about 4.56 W; wind differences were at most about 0.006 MW in this check. |
| Wind data mapping | All six original workbooks were examined; full retained timestamp/weather/power tables matched original sources 6, 4 and 3 respectively. |
| Full-record forecast CLI | PINN inference for archived `Turbine_2` exported 35,112 prediction rows. |
| Short real-scene schedule | A 300-step smoke run with six vehicles and a constant test supply produced finite states and valid vehicle SoC values. This is a test input, not a paper result. |
| Full paired schedule | G1 ran both branches for 10,600 steps each and generated case histories, figures and summaries. Completion counts matched the supplied reference; the largest absolute difference over numeric summary fields was approximately 2.57e-9. |
| PV plotting command | All three archived inverter result sets produced their figures, plus the combined metric figure. |
| Flight preprocessing | Both preprocessing scripts ran. All three regenerated aligned profiles matched the distributed aligned-time, power, height and battery-percentage columns exactly in the checked environment. |

The saved-prediction comparisons do not establish that the original files were all generated by one clean training run. Small differences across machines or library versions are recorded explicitly. G1 is the high-initial-charge case and does not exercise all congestion/charging behavior; only one complete group, not all twelve, was rerun during preparation. Full multi-epoch retraining, physical hardware operation, and exhaustive output-figure review were not performed. Wind and grouped-scheduling plotting code is included; only PV plotting and the figures from the G1 runner were exercised end to end.

`verification_report.json` contains the model/schema/short-schedule checks. `verification_extras.json` contains the full-pair comparison, full wind-inference row count and flight-profile comparisons. `scripts/check_release.py` can rerun the model/schema/short-schedule checks on another machine; it writes a new report under `runs/` and does not alter the reference reports.
